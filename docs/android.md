# Android app (APK)

The APK is a **Capacitor** shell: a native Android app whose WebView loads the
Next.js app from a server. It can't be bundled offline — the app uses Server
Actions and server components — so the phone must be able to reach the server.
`capacitor.config.ts` reads the server from `CAP_SERVER_URL`.

| Build | `CAP_SERVER_URL` | Needs |
|---|---|---|
| LAN test | `http://<PC Wi-Fi IP>:3000` | `npm run dev` running, phone on the same Wi-Fi |
| Production | `https://<your domain>` | the app deployed (`docs/deployment.md`) |

Cleartext (`http`) is enabled only when the URL is `http://`; https builds ship with it off.

## Build a debug APK

Prerequisites (one-off): **JDK 21**, Android SDK (platform 36 is fetched by Gradle
on first build). Set them for the shell you build in:

```powershell
$env:JAVA_HOME   = "C:\Users\kelvi\tools\jdk21-x\jdk-21.0.12.1+1"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
# Corporate/AV networks re-sign HTTPS; make Java trust the Windows cert store
# (verification stays ON — it just uses the OS trust store).
$env:JAVA_TOOL_OPTIONS = "-Djavax.net.ssl.trustStoreType=WINDOWS-ROOT"

$env:CAP_SERVER_URL = "http://192.168.1.20:3000"   # your PC's Wi-Fi IP
npm run android:apk
# -> android/app/build/outputs/apk/debug/app-debug.apk
```

For the LAN build also set `ALLOWED_DEV_ORIGINS=<PC Wi-Fi IP>` in `.env.local`
(`next.config.ts` `allowedDevOrigins`) and restart `npm run dev`; otherwise Next 16
blocks the phone's dev-asset requests.

Install: copy the APK to the phone and open it (allow "install unknown apps"), or
`adb install -r app-debug.apk`.

## Gotchas

- **The Wi-Fi IP changes** (DHCP / hotspot). When it does, rebuild with the new
  `CAP_SERVER_URL` and update `ALLOWED_DEV_ORIGINS`. A deployed https URL ends this.
- **Windows Firewall** may block inbound `:3000` from the phone. Allow Node on
  *Private* networks, or (admin PowerShell):
  `New-NetFirewallRule -DisplayName "Next dev 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow -Profile Private`
- **WebView floor = Chrome 111** (`android.minWebViewVersion`; Tailwind v4 / React 19
  need it). Older WebViews show `capacitor-www/offline.html` instead of a broken
  page. Phones update WebView through Google Play, so this mainly affects old or
  Play-less devices. Emulator images ship an old WebView — test on a real phone or
  a recent image.
- `android/app/src/main/assets/capacitor.config.json` is generated by `cap sync`
  and git-ignored (it embeds the server URL).
- `npm audit` reports 4 moderate advisories in `@capacitor/cli`'s build-time
  dependencies (`xcode` → `uuid`, `qs`). Dev tooling only — not shipped in the app.

## Before Google Play

Icons, splash, release signing, the signed-bundle build and the store listing are done — the
step-by-step (keystore, `npm run android:aab`, Play Console forms, Data safety answers, launch
checklist) is in **`docs/play-store.md`**.

- Payments: real gateways (Stripe/Billplz) redirect to a browser; the mock gateway
  is in-app so it works in the WebView today — but it must be switched off before a Play release.
- The emulator images here ship an old WebView (83), below the app's floor, so they show the
  "can't open" screen; use a real phone (or an image with Chrome/WebView 111+) to see the app.
